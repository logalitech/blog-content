The SAP tutorials for the Mobile Development Kit (MDK) set up the editor in the cloud, in a dev space in SAP Business Application Studio (BAS).

The editor does not have to be there. Since [version 2.0](https://community.sap.com/t5/technology-blog-posts-by-sap/sap-mobile-development-kit-editor-2-0-one-editor-every-platform/ba-p/14384812), the Mobile Development Kit extension is a single extension for both Business Application Studio and VS Code, with the same graphical editors, so the entire environment fits into a local VS Code.

For SAP Mobile Services, it makes no difference which editor deploys the application.

Before AI coding agents, Business Application Studio had a real advantage: a dev space came prepared with all the tools installed, and a quick application required no setup on the developer's machine. Today, a single request to a coding agent installs Node.js, the Cloud Foundry CLI, the extensions and the generator, and that advantage disappears.

A local VS Code is fast, runs the extensions the developer already uses and keeps working offline from the cloud, which makes it a better option for most developers.

## Step 1. Install the tools

Three things are needed on the machine: VS Code, Node.js and the Cloud Foundry CLI.

## Step 2. Install the extensions

Four extensions from the VS Code marketplace are installed. It is best to search for them by their identifier, because several SAP extensions have similar names.

| Extension | Identifier | Purpose |
|---|---|---|
| Mobile Development Kit Editor | `SAPSE.vsc-extension-mdk` | The graphical editors, validation, build and deployment |
| Application Wizard | `SAPOS.yeoman-ui` | The project creation wizard |
| Cloud Foundry Tools | `SAPOSS.vscode-cf-tools` | The login with which the MDK extension reaches Mobile Services |
| SAP Business Application Studio toolkit | `SAPOSS.app-studio-toolkit` | It installs itself along with the Application Wizard |

## Step 3. Install the MDK generator

The Application Wizard creates projects from the Yeoman generators installed on the machine. The MDK templates come from the SAP generator:

```bash
npm install -g yo @sap/generator-mdk
```

## Step 4. Log in to Cloud Foundry

The Cloud Foundry view opens in the activity bar, or you run `CF: Login to Cloud Foundry` from the command palette. You enter the subaccount's API endpoint, which the SAP BTP cockpit shows on the subaccount's **Overview** page, under **Cloud Foundry Environment**, and you log in with credentials (**Credentials**) or with an SSO passcode (**SSO Passcode**).

![Cloud Foundry Sign In and Targets page in VS Code, with the endpoint field and the choice between Credentials and SSO Passcode](/images/blog/sap-mdk-vs-code-alternativa-bas-05-cloud-foundry-sign-in.png)

Then you run `CF: Set Org and Space` and choose the organization and space that contain the Mobile Services application. The subaccount, organization and space hierarchy is explained in [The Cloud Foundry model: orgs, spaces and apps without the mystery](/en/blog/cf-modelo-org-space-app/).

![VS Code command palette with the CF: Set Org and Space command](/images/blog/sap-mdk-vs-code-alternativa-bas-06-cf-set-org-and-space.png)

## Step 5. Create the project

An empty folder is opened in VS Code, because the wizard creates the project, by default, in the open folder. Then the command palette is opened with Cmd+Shift+P, or Ctrl+Shift+P on Windows, and `MDK: Create Project with Wizard` is run.

To learn how to build a first MDK application step by step, SAP offers the mission [Create Your First MDK Application](https://developers.sap.com/tutorials/mission-create-your-first-mdk-application).

## Working on the MDK app with local agents

The app is now a folder on the developer's machine, and everything the editor offers works on it, including coding agents. Agents such as Claude Code, Codex, GitHub Copilot, Cline and OpenCode read and modify the same pages, actions, rules and services that the graphical editors open. A page generated by an agent can be tweaked by hand in the Page Editor, and the agent can connect a hand-designed page to its actions and data.

![MDK project generated in VS Code, with its folders in the explorer, Main.page open in the graphical Page Editor and the coding agents in the editor title bar](/images/blog/sap-mdk-vs-code-alternativa-bas-07-proyecto-mdk-y-agentes.png)

![Main.page open as JSON in the VS Code text editor, with the coding agents in the editor title bar](/images/blog/sap-mdk-vs-code-alternativa-bas-08-main-page-editor-de-texto.png)

So that the agent works with up-to-date MDK knowledge, and not with what it remembers, SAP publishes an open-source MCP server for MDK:

```bash
npm install -g @sap/mdk-mcp-server
```

The server gives the agent the MDK schema, the project templates and the MDK command-line tools. With them, the agent can query what a control supports, generate a page or validate, build and deploy the app when asked. SAP's tutorial [Set Up MCP Server for MDK Development](https://developers.sap.com/tutorials/cp-mobile-dev-kit-mcp-setup) explains how to connect it to VS Code.

Another MCP server from the SAP ecosystem, the one that exposes a SAP CAP service to an agent, is described in [SAP CAP as an MCP server: one annotation and three surprises](/en/blog/sap-cap-as-mcp-server/).
