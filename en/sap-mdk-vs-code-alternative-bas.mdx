SAP's tutorials for the Mobile Development Kit set up the editor in a dev space in SAP Business Application Studio (BAS).

Since [version 2.0](https://community.sap.com/t5/technology-blog-posts-by-sap/sap-mobile-development-kit-editor-2-0-one-editor-every-platform/ba-p/14384812), released in May 2026, the Mobile Development Kit extension is a single extension for both BAS and VS Code, with the same graphical editors. The project format is the same in both, so a project can move between them through git.

## VS Code or BAS

|                                | Local VS Code                                                                               | BAS                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Setup                          | VS Code, Node.js, the Cloud Foundry CLI, four extensions and the MDK generator, on each machine | a preconfigured SAP Mobile Application dev space |
| Cloud Foundry login to deploy  | required                                                                                    | required, the same login                    |
| Without a connection           | the graphical editors and validation work; deploying needs Mobile Services                  | needs a connection                          |
| Only available here            | `MDK: Create Project with Wizard` and, in SAP's comparison, on-device debugging of rules    | the Storyboard and the Service Center       |

The local setup suits a developer who already works in VS Code with their own extensions and coding agents. BAS suits a team that wants every developer on the same preconfigured dev space, or a project that needs the Storyboard.

The steps below cover creating, validating and deploying an app locally. Debugging rules on a device needs a client built with the MDK local build toolchain, which is not covered here.

## 1. Install the tools

Three things on the machine: VS Code, Node.js and the Cloud Foundry CLI.

## 2. Install the extensions

Four extensions from the marketplace. Search by ID, because several SAP extensions have similar names.

| Extension                               | ID                          | What it does                                                      |
| --------------------------------------- | --------------------------- | ----------------------------------------------------------------- |
| Mobile Development Kit Editor           | `SAPSE.vsc-extension-mdk`   | the graphical editors, validation, build and deploy               |
| Application Wizard                      | `SAPOS.yeoman-ui`           | the project creation wizard                                       |
| Cloud Foundry Tools                     | `SAPOSS.vscode-cf-tools`    | the login through which the MDK extension reaches Mobile Services |
| SAP Business Application Studio toolkit | `SAPOSS.app-studio-toolkit` | installs itself with the Application Wizard                       |

For a project that already exists and is cloned from git, the first and third are enough.

## 3. Install the MDK generator

The Application Wizard builds projects from the Yeoman generators installed on the machine. The MDK templates come from SAP's generator, which SAP's setup pages do not mention. Without it, the wizard reports `Could not find any generators.`

```bash
npm install -g yo @sap/generator-mdk
```

## 4. Log in to Cloud Foundry

The Cloud Foundry login is how the MDK extension reaches SAP Mobile Services to deploy. BAS asks for the same login.

Open the Cloud Foundry view in the activity bar, or run `CF: Login to Cloud Foundry` from the command palette. Enter the API endpoint of the subaccount, which the SAP BTP cockpit shows on the subaccount's **Overview** page under **Cloud Foundry Environment**, and sign in with credentials or an SSO passcode.

![The Cloud Foundry Sign In and Targets page in VS Code, with the endpoint field and a choice between Credentials and SSO Passcode](/images/blog/sap-mdk-vs-code-alternativa-bas-05-cloud-foundry-sign-in.png)

Then run `CF: Set Org and Space` and choose the organization and space that hold your Mobile Services app. The hierarchy of subaccount, organization and space is explained in [The Cloud Foundry model: orgs, spaces and apps demystified](/en/blog/cf-modelo-org-space-app/).

![The command palette with CF: Set Org and Space](/images/blog/sap-mdk-vs-code-alternativa-bas-06-cf-set-org-and-space.png)

Deploying needs the Space Developer role in that space. With Space Manager or Space Auditor the login works and the cockpit shows the app, but every deploy fails, and the error does not name the role.

On macOS, if the Cloud Foundry Tools log shows `cf: command not found` after a login attempt, VS Code was started without the Homebrew path. Starting it from a terminal with `code <folder>` fixes it.

## 5. Create the project

Open an empty folder in VS Code, since the wizard creates the project in the open folder by default. Then open the command palette with Cmd+Shift+P, or Ctrl+Shift+P on Windows, and run `MDK: Create Project with Wizard`.

To check the setup, run `MDK: Validate Application`, then `MDK: Deploy`. Validation works offline; the deploy is the step that proves the connection to Mobile Services, and it ends with a revision number. If a step fails, `.build/log.txt` in the project holds the exact command the extension ran and its full output.

To learn how to build a first MDK app step by step, follow SAP's mission [Create Your First MDK Application](https://developers.sap.com/tutorials/mission-create-your-first-mdk-application).

## Working on the app with coding agents

The project is a folder on the developer's machine, so coding agents such as Claude Code, Codex, GitHub Copilot, Cline and OpenCode work on the same pages, actions, rules and services that the graphical editors open. A page an agent generates can be adjusted by hand in the Page Editor, and a page designed by hand can be wired up by the agent.

![The generated MDK project in VS Code, with its folders in the explorer, Main.page open in the graphical Page Editor, and the coding agents in the editor title bar](/images/blog/sap-mdk-vs-code-alternativa-bas-07-proyecto-mdk-y-agentes.png)

![The same Main.page open as JSON in the text editor, with the coding agents in the editor title bar](/images/blog/sap-mdk-vs-code-alternativa-bas-08-main-page-editor-de-texto.png)

SAP publishes an open source MCP server for MDK, so the agent can check the MDK schema instead of relying on what its model remembers:

```bash
npm install -g @sap/mdk-mcp-server
```

It gives the agent the MDK schema, the project templates and the MDK command line tools, so it can look up what a control supports, generate a page, and validate, build and deploy the app. SAP's tutorial [Set Up MCP Server for MDK Development](https://developers.sap.com/tutorials/cp-mobile-dev-kit-mcp-setup) connects it to VS Code.

A deploy from the agent goes to the same Mobile Services app as a deploy from the editor, and reaches its users on their next start. Keep the deploy as a step a person approves, and review the agent's changes before it.

Another MCP server in the SAP ecosystem, one that exposes an SAP CAP service to an agent, is described in [SAP CAP as an MCP server: one annotation and three surprises](/en/blog/sap-cap-as-mcp-server/).
