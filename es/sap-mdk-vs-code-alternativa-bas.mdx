Los tutoriales de SAP para el Mobile Development Kit (MDK) preparan el editor en un espacio de desarrollo (dev space) de SAP Business Application Studio (BAS).

Desde la [versión 2.0](https://community.sap.com/t5/technology-blog-posts-by-sap/sap-mobile-development-kit-editor-2-0-one-editor-every-platform/ba-p/14384812), publicada en mayo de 2026, la extensión Mobile Development Kit es una sola extensión para BAS y para VS Code, con los mismos editores gráficos. El formato del proyecto es el mismo en los dos, de modo que un proyecto puede pasar de uno a otro a través de git.

## VS Code o BAS

| | VS Code local | BAS |
|---|---|---|
| Preparación | VS Code, Node.js, la CLI de Cloud Foundry, cuatro extensiones y el generador de MDK, en cada equipo | Un dev space SAP Mobile Application ya configurado |
| Inicio de sesión en Cloud Foundry para desplegar | Obligatorio | Obligatorio, el mismo |
| Sin conexión | Los editores gráficos y la validación funcionan; el despliegue necesita Mobile Services | Necesita conexión |
| Solo disponible aquí | `MDK: Create Project with Wizard` y, según la comparativa de SAP, la depuración de reglas en el dispositivo | El Storyboard y el Service Center |

El entorno local encaja con un desarrollador que ya trabaja en VS Code con sus propias extensiones y agentes de programación. BAS encaja con un equipo que quiere a todos sus desarrolladores en el mismo dev space preconfigurado, o con un proyecto que necesita el Storyboard.

Los pasos siguientes cubren la creación, la validación y el despliegue de una aplicación en local. Depurar reglas en un dispositivo requiere un cliente compilado con la MDK local build toolchain, que este artículo no trata.

## Paso 1. Instalar las herramientas

En el equipo hacen falta tres cosas: VS Code, Node.js y la CLI de Cloud Foundry.

## Paso 2. Instalar las extensiones

Se instalan cuatro extensiones del marketplace de VS Code. Conviene buscarlas por su identificador, porque varias extensiones de SAP tienen nombres parecidos.

| Extensión | Identificador | Función |
|---|---|---|
| Mobile Development Kit Editor | `SAPSE.vsc-extension-mdk` | Los editores gráficos, la validación, la compilación y el despliegue |
| Application Wizard | `SAPOS.yeoman-ui` | El asistente de creación de proyectos |
| Cloud Foundry Tools | `SAPOSS.vscode-cf-tools` | El inicio de sesión con el que la extensión de MDK llega a Mobile Services |
| SAP Business Application Studio toolkit | `SAPOSS.app-studio-toolkit` | Se instala sola con el Application Wizard |

Para un proyecto que ya existe y se clona desde git, bastan la primera y la tercera.

## Paso 3. Instalar el generador de MDK

El Application Wizard crea los proyectos a partir de los generadores de Yeoman instalados en el equipo. Las plantillas de MDK proceden del generador de SAP, que las páginas de instalación de SAP no mencionan. Sin él, el asistente muestra `Could not find any generators.`

```bash
npm install -g yo @sap/generator-mdk
```

## Paso 4. Iniciar sesión en Cloud Foundry

El inicio de sesión en Cloud Foundry es la vía por la que la extensión de MDK llega a SAP Mobile Services para desplegar. BAS pide el mismo inicio de sesión.

Se abre la vista de Cloud Foundry en la barra de actividades o se ejecuta `CF: Login to Cloud Foundry` desde la paleta de comandos. Se introduce el endpoint de la API de la subcuenta, que el SAP BTP cockpit muestra en la página **Overview** de la subcuenta, en el apartado **Cloud Foundry Environment**, y se inicia sesión con credenciales (**Credentials**) o con un código de acceso SSO (**SSO Passcode**).

![Página Cloud Foundry Sign In and Targets de VS Code, con el campo del endpoint y la elección entre Credentials y SSO Passcode](/images/blog/sap-mdk-vs-code-alternativa-bas-05-cloud-foundry-sign-in.png)

Después se ejecuta `CF: Set Org and Space` y se eligen la organización y el espacio que contienen la aplicación de Mobile Services. La jerarquía de subcuenta, organización y espacio se explica en [El modelo de Cloud Foundry: orgs, spaces y apps sin misterio](/blog/cf-modelo-org-space-app/).

![Paleta de comandos de VS Code con el comando CF: Set Org and Space](/images/blog/sap-mdk-vs-code-alternativa-bas-06-cf-set-org-and-space.png)

Para desplegar hace falta el rol Space Developer en ese espacio. Con Space Manager o Space Auditor, el inicio de sesión funciona y el cockpit muestra la aplicación, pero todos los despliegues fallan, y el error no indica el rol.

En macOS, si el registro de Cloud Foundry Tools muestra `cf: command not found` tras un intento de inicio de sesión, VS Code se ha abierto sin la ruta de Homebrew. Se soluciona abriéndolo desde un terminal con `code <carpeta>`.

## Paso 5. Crear el proyecto

Se abre una carpeta vacía en VS Code, porque el asistente crea el proyecto, por defecto, en la carpeta abierta. Después se abre la paleta de comandos con Cmd+Shift+P, o Ctrl+Shift+P en Windows, y se ejecuta `MDK: Create Project with Wizard`.

Para comprobar el entorno, se ejecuta `MDK: Validate Application` y después `MDK: Deploy`. La validación funciona sin conexión; el despliegue es el paso que demuestra la conexión con Mobile Services, y termina con un número de revisión. Si un paso falla, el fichero `.build/log.txt` del proyecto contiene el comando exacto que ejecutó la extensión y su salida completa.

Para aprender a construir paso a paso una primera aplicación MDK, SAP ofrece la misión [Create Your First MDK Application](https://developers.sap.com/tutorials/mission-create-your-first-mdk-application).

## Trabajar en la aplicación con agentes de programación

El proyecto es una carpeta en el equipo del desarrollador, de modo que agentes de programación como Claude Code, Codex, GitHub Copilot, Cline y OpenCode trabajan sobre las mismas páginas, acciones, reglas y servicios que abren los editores gráficos. Una página que genera un agente se puede ajustar a mano en el Page Editor, y el agente puede conectar a sus acciones y datos una página diseñada a mano.

![Proyecto MDK generado en VS Code, con sus carpetas en el explorador, Main.page abierto en el Page Editor gráfico y los agentes de programación en la barra de título del editor](/images/blog/sap-mdk-vs-code-alternativa-bas-07-proyecto-mdk-y-agentes.png)

![Main.page abierto como JSON en el editor de texto de VS Code, con los agentes de programación en la barra de título del editor](/images/blog/sap-mdk-vs-code-alternativa-bas-08-main-page-editor-de-texto.png)

SAP publica un servidor MCP de código abierto para MDK, para que el agente consulte el esquema de MDK en lugar de fiarse de lo que recuerda su modelo:

```bash
npm install -g @sap/mdk-mcp-server
```

El servidor da al agente el esquema de MDK, las plantillas de proyecto y las herramientas de línea de comandos de MDK, de modo que puede consultar qué admite un control, generar una página y validar, compilar y desplegar la aplicación. El tutorial de SAP [Set Up MCP Server for MDK Development](https://developers.sap.com/tutorials/cp-mobile-dev-kit-mcp-setup) explica cómo conectarlo a VS Code.

Un despliegue desde el agente va a la misma aplicación de Mobile Services que un despliegue desde el editor y llega a sus usuarios en su siguiente inicio. Conviene que el despliegue sea un paso que aprueba una persona, después de revisar los cambios del agente.

Otro servidor MCP del ecosistema SAP, el que expone un servicio SAP CAP a un agente, se describe en [SAP CAP como servidor MCP: una anotación y tres sorpresas](/blog/cap-mcp-servidor-agentes-ia/).
